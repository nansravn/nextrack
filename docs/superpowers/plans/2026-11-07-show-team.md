# The show team (project 2b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give NEXTRACK a team of agents that runs a light show end to end inside Claude Code:
- a project skill, `show-team`, that the main session follows as the director;
- four role agents;
- five critic lenses and the dispatch templates;
- a hook that asks the owner before anything writes SoundSwitch;
- a rehearsal of the whole rite.

**Architecture:** The director is the main session following `.claude/skills/show-team/SKILL.md`.
- **Role agents:** they live in `.claude/agents/`. They take a brief file and answer with a short report, and the full report goes to a file in a scratch run folder.
- **Facts:** they come from the 2a tools (`brief`, `report`, `zoom`, `compare`, `book`). Critics judge through lens rubrics and never see the author's reasoning.
- **The ledger:** `lightshows/shows/<id>/ledger.md` carries the run's state, so a run can resume.
- **The guard:** a `PreToolUse` hook makes every SoundSwitch write ask the owner.

**Tech Stack:** Claude Code project skills, subagents and hooks; Python 3.12 for the hook and its tests; pytest; uv.

**Spec:** `docs/superpowers/specs/2026-11-07-show-team-design.md`, Part B. Read sections B1-B9 and Decisions 10-23.

**Branch:** `feat/show-team-skill`, stacked on `feat/show-team` (2a). The owner merges 2a first, and this branch is then rebased onto `main`.

## Global Constraints

- Setup and commands: `uv sync`, `uv run pytest`, `uv run scripts/check_repo.py`. Never pip or poetry.
- **Language:**
  - Skill, agent, lens and template files are written in English (code and docs language).
  - The ids and lens names are the spec's: `monotonia`, `drops`, `energia-da-musica`, `arco-do-set`, `briefing`.
  - Everything the team writes for the owner is in pt-BR: show prose, the light plan, the ledger, critic findings, the final report.
- **Agent frontmatter:** `name`, `description`, `tools` and `model`.
  - Allowed `model` values are `opus`, `sonnet`, `haiku` and `inherit`.
  - The critic's model is `opus`.
  - The reader and the critic have no `Write` or `Edit` tool.
- **Hook output:** exit 0 with
  `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "ask", "permissionDecisionReason": "..."}}`,
  or exit 0 with no output. Never exit 2.
- **What the team may never do:** push, open a PR, merge, or run `nextrack_lights.py ... --apply`. It may never edit a generated choreography (`lightshows/tracks/*.yml` with the generated header).
- **Commits:** no machine path, user name or local config in a committed file. Run
  `git diff --cached | grep -iE "/home/|/mnt/|C:\\\\Users"` before every commit; it must print nothing.
- **Commit subjects:** imperative English with no `feat:` prefix. Every message ends with:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01TJp8YhHnGhN5eQ9PfRzAsC
  ```
- **Definition of done for each task:** `uv run pytest` and `uv run scripts/check_repo.py` pass.

## Review Focus

1. **Hook input that is not a plain Bash command** must exit 0 with no output, never a
   traceback. That covers malformed JSON, another tool, a missing `command`, and a command that
   shlex cannot split. Test in Task 1.
2. **Commands that mention `nextrack_lights.py` without writing** (`apply` without `--apply`,
   `render`, `status`) must not ask, and `nextrack_tags.py --apply` must not either: this guard
   is SoundSwitch's only. Test in Task 1.
3. **A skill file naming an agent, lens or template that does not exist**, or the reverse, must
   fail a test. Test in Task 5.
4. **A resumed run** must find its place from the ledger alone: the state line format must be
   unambiguous. Exercised in the Task 7 rehearsal.
5. **A critic dispatch must not hand over the author's reasoning.** The critic template names
   what the critic reads, and the agent file lists what it must not open: the ledger and the
   run folder's designer reports. Test in Task 4 (template text) and Task 2 (agent text).

### Task 2: The role agents

**Files:**
- Create: `.claude/agents/show-reader.md`, `.claude/agents/show-designer.md`,
  `.claude/agents/show-critic.md`, `.claude/agents/gesture-engineer.md`,
  `tests/test_show_team_files.py`

**Interfaces:**
- Produces four agent files:

| name | tools | model | body says |
|---|---|---|---|
| `show-reader` | `Read, Grep, Glob, Bash` | `sonnet` | reads the night's design cold (`show.yml`, the light plan with its cards, `brief`) and lists, ranked, each place it would have to guess and why the guess matters; never edits; writes its report to the path in its brief |
| `show-designer` | `Read, Grep, Glob, Bash, Write, Edit` | `sonnet` | writes one unit (a track file, or a mix: the outgoing handover and the incoming opening) in its scratch copy only. It works from its brief: the story and identity, its card, the neighbours' cards and handovers, the usage record, its `report --track` slice, the constraints verbatim. It writes three options, each with a one-line summary and how typical it is, and chooses against the card and the usage record. It builds with `build <copy> --out <copy>/out`, and asks for a missing gesture in its report instead of writing code. It never edits `lightshows/tracks/` or the committed show |
| `show-critic` | `Read, Grep, Glob, Bash` | `opus` | judges through one lens (the rubric file named in its brief), or compares variants blind in both orders. It reads the story, identity, plan and cards and runs the views. It must not open the show's `ledger.md` or the run folder's designer reports. It looks for where the night is weakest and most predictable and never approves by default. Every finding has a lens, a severity (`grave`/`moderado`/`menor`), a unit, evidence (a report or zoom line with bars and clock), a problem and a direction, in pt-BR |
| `gesture-engineer` | `Read, Grep, Glob, Bash, Write, Edit` | `sonnet` | adds one gesture through CLAUDE.md's "Add a gesture" checklist, test first, and runs the suite; never touches a show |

- Every body ends with the reply contract: the full report goes to the path in the brief, and
  the reply is at most 15 lines (status, files, one-line summary, concerns).

  - `test_the_critic_runs_on_opus`;
  - `test_the_reader_and_the_critic_cannot_write`;
  - `test_the_critic_is_told_not_to_read_the_authors_reasoning` (the body names `ledger.md` and
    "designer reports");
  - `test_every_agent_states_the_reply_contract` ("15 lines" and "report").
- [ ] **Step 2: Run them; expect FAIL.**

### Task 3: The critic lenses

**Files:**
- Create: `.claude/skills/show-team/lenses/monotonia.md`, `drops.md`, `energia-da-musica.md`,
  `arco-do-set.md`, `briefing.md`
- Modify: `tests/test_show_team_files.py`

**Interfaces:**
- Each lens file has the sections `## Judges`, `## Run` (the exact commands, with `<show>`
  standing for the folder), `## Questions`, `## Severity` (what is `grave`, `moderado` and
  `menor` in this lens) and `## Finding format`.

| lens | judges | runs |
|---|---|---|
| `monotonia` | repetition, static stretches, neighbours alike, predictable drops, the chaos guard | `report <show> --section variety,identity`, `report <show> --section tracks` for the static runs' music |
| `drops` | contrast, change and freshness at the night's top drops, the main drop of each track, builds into drops | `report <show> --section drops,builds,peaks,hits`, `zoom <show> "<track>" <bar>` for each top drop |
| `energia-da-musica` | each track's light following its music: shape, direction, lag, missed boundaries | `report <show> --section follows,tracks` |
| `arco-do-set` | the night following the owner's energy and arc: headroom, staircase, steps, breathers | `report <show> --section arc,summary`, `brief <set>` |
| `briefing` | fidelity to the story, identity and cards; restraint (budgets, rare resources); palette and fixture roles | `report <show> --section identity,budget,arrivals`, the light plan's cards |

- **Severity:** `grave` is a criterion that fails at a top drop or across a whole track (or
  the night, for `arco-do-set`). `menor` is polish. `moderado` is everything between.

- **Sections, in order:**
  - **`## When to use`**.
  - **`## What the owner gives and keeps`:** the set and its hot cues B/G; the owner's tasks
    (presets, measuring the room, X11); never push, PR, merge or apply.
  - **`## The run folder and the ledger`:**
    - the folder is `<scratch>/show-team/<show-id>/<YYYY-MM-DD-HHMM>/`;
    - the ledger format of the manual (`lightshows/shows/README.md`, "The ledger");
    - after every phase, a state line `Estado: fase <n> (<name>) concluída — <YYYY-MM-DD HH:MM>`;
    - one commit per round.
  - **`## Checklist`:** phases 0-9 to copy into the director's reply and keep current.
  - **`## The phases`:** spec B3, phase by phase, with the exact commands. Phase 0 includes the
    resume check, the worktree and branch, and the dispatch estimate. Phase 1 is inputs. Phase
    2 is the concept (three concepts with their likelihood) or the diagnosis (with the
    preservation contract in `compare --keep` terms). The concept writes `show.yml` and the
    light plan (`lightshows/sets/<id>.md`), whose `## Cartões` section holds one card per track
    (energy target, role in the arc, arrival idea, peak moment, look family). Then come the
    cold read, design batches (at most 5, disjoint files) and gates. A gesture the designers
    ask for is dispatched to the `gesture-engineer` and then to a code review (superpowers'
    requesting-code-review pattern) before any designer uses it. Then critique (scope
    discipline), consolidation (fix, decision or later; drop findings without evidence),
    selection (judge template) and delivery.
  - **`## Stopping and self-healing`:** spec B5 (3 rounds per unit, 2 night passes, minors
    never loop, a grave on the third round goes upstream once and then stops, budget, resume).
  - **`## Delivery`:** the gates, `check_repo`, `pytest`, `compare --keep` on a rework, and the
    book. The book is written to the run folder and published as a private Artifact when the
    tool is available, else its path is given. Then the ledger, the commits, and the pt-BR
    report to the owner. The run stops at the branch.
  - **`## Placeholders`:** a table of every template placeholder and who fills it.
  - **`## Measuring the team`:** spec B9.
