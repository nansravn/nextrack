# Musical Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tool that turns each track's audio into a committed musical map (voices, onsets, register, phrases, sections, drops, hot cues) on the choreography's bar grid, a set timeline from the rekordbox playlist, and the map drawn in the simulator.

**Architecture:** A numpy-only library (`musical_map.py`) computes features from stem arrays and owns the map file (build, YAML, validation, staleness). A small pure module (`set_timeline.py`) computes transitions from maps and cues. The CLI (`nextrack_map.py`) wires the heavy adapters (Demucs, pyrekordbox), which are imported lazily and replaced by fakes in tests. `check_repo.py` and `nextrack_lights.py render` read the map files.

**Tech Stack:** Python 3.14 (`.python-version`), numpy, soundfile, PyYAML; optional group `analysis`: demucs, torch, pyrekordbox, sqlcipher3-wheels; pytest.

**Spec:** `docs/superpowers/specs/2026-11-05-musical-map-design.md`

## Global Constraints

- Default dependencies gain only `numpy` and `soundfile`. Demucs, PyTorch, `pyrekordbox` and `sqlcipher3-wheels` go in a non-default dependency group `analysis`; `uv sync --locked` (CI) must not install them.
- No test imports torch, demucs or pyrekordbox, opens a real rekordbox database or reads real audio. Synthetic audio only, under `tmp_path`.
- Read-only on audio, rekordbox (only through a copy of `master.db`, `-wal`, `-shm` in a temp folder) and the SoundSwitch project.
- Folders come from options or environment variables only: `--project`/`NEXTRACK_SOUNDSWITCH_PROJECT`, `--root`/`NEXTRACK_AUDIO_ROOT`, `--rekordbox`/`NEXTRACK_REKORDBOX_DIR`. No machine path in code, docs, maps or commits.
- Bars come from `soundswitch_format.Grid` built from the script's tempo anchors: bar 1 beat 1 is the first anchor; audio before it is not in the map. A step is a 1/16 note (16 per bar).
- Voices, in this order: `vocals`, `kick`, `perc`, `bass`, `other`. Section kinds: `intro`, `groove`, `break`, `build`, `drop`, `outro`.
- Code, keys, docs, commit messages in English; simulator labels in pt-BR. Commit subjects are imperative sentences (`Add …`, `Fix …`), no `feat:` prefix, ending with the session's attribution lines.
- `djmdCue.Kind` → hot cue: 1 A, 2 B, 3 C, 5 D, 6 E, 7 F, 8 G, 9 H; 0 (memory cue) is ignored.
- Run `uv run scripts/check_repo.py` and `uv run pytest` before every commit; both must pass.

## Review Focus

1. Audio at 48 kHz (or any rate other than the model's 44.1 kHz): bars and digits must come out the same as at 44.1 kHz. Test in Task 4.
2. A mono file: treated as two equal channels (balance reads `c`). Test in Task 2.
3. Audio before the first tempo anchor (Yamore's downbeat is at 3.998 s) and a last bar cut short by the end of the file: the pickup is ignored, the partial bar is bar `bars`, and every string still has the right length. Test in Task 4.
4. A playlist name that matches no playlist or several, and a playlist track that SoundSwitch or rekordbox does not know: a clear refusal naming the candidates, never a guess. Tests in Tasks 5 and 6.
5. File names that differ only in Unicode form (NFC/NFD: "Baianá", "Cesária") or case, between the TrackMap path, the library and rekordbox. Tests in Task 5.

### Task 2: Voices and level features

**Files:**
- Modify: `scripts/musical_map.py`
- Create: `tests/test_musical_map_features.py` (and a small synthetic-audio helper module `tests/synth.py` with tone, noise-burst, click and pan helpers used by Tasks 2-4)

**Interfaces:**
- Consumes: `VOICES`, `STEPS_PER_BAR`, `soundswitch_format.Grid`.
- Produces:
  - `step_edges_ms(grid: ssf.Grid, audio_ms: int) -> np.ndarray`: step boundaries from bar 1 beat 1 to the end of the audio; length `bars*16 + 1`, last edge clipped to `audio_ms`; `bars = grid.bar_at(audio_ms - 1)`.
  - `voices_from_stems(stems: dict[str, np.ndarray], sr: int) -> dict[str, np.ndarray]`: input keys `vocals, drums, bass, other`, arrays shaped `(n, 2)` (a 1-D array is mono and is duplicated); the drums stem is split by frequency into `kick` (below ~150 Hz) and `perc` (the rest). Returns the five `VOICES`, `(n, 2)` float32.
  - `rms_db(x: np.ndarray, sr: int, edges_ms: np.ndarray) -> np.ndarray`: mono RMS in dB per interval (−120 for silence or an empty interval).
  - `level_digits(db: np.ndarray, voice_loud_db: float, mix_loud_db: float) -> str`: `9` at the voice's loud level, one digit per 3 dB below, `0` at or under 27 dB below; all `0` when `voice_loud_db < mix_loud_db - BLEED_DB` (`BLEED_DB = 30.0`). "Loud level" = 95th percentile of the per-bar dB.
  - `entries_exits(bar_digits: str) -> tuple[list[int], list[int]]`: entry = first bar with digit ≥ 5 after at least two bars ≤ 2 (bar 1 counts as an entry when it is ≥ 5); exit = last bar ≥ 5 before at least two bars ≤ 2 or the end.
  - `balance_letters(x: np.ndarray, sr: int, bar_edges_ms: np.ndarray) -> str`: L−R level difference per bar: ≥ 6 dB `L`, ≥ 2 dB `l`, ≤ −6 `R`, ≤ −2 `r`, else `c` (silent bars `c`).

### Task 6: CLI `nextrack_map.py`: `analyze`, `cues`, `show`

**Files:**
- Create: `scripts/nextrack_map.py`
- Create: `tests/test_nextrack_map_cli.py`

**Interfaces:**
- Consumes: Tasks 1-5, `soundswitch_format.Project`, `check_repo` pool loading and `same_track`/`norm`.
- Produces: `main(argv: list[str] | None = None) -> int`; module attributes the tests replace: `make_separator(device) -> separator` (defaults to `demucs_separator`) and `open_rekordbox` (re-exported from `rekordbox_cues`).
  - `demucs_separator(device: str | None) -> Callable[[np.ndarray, int], tuple[dict[str, np.ndarray], int]]`: lazy imports (missing `analysis` group → the same install message as `open_rekordbox`); `get_model("htdemucs")`, resample to the model's rate when the file's differs, normalise and denormalise like Demucs's own `separate`, `apply_model`; returns `{vocals, drums, bass, other}` as `(n, 2)` arrays and the model's sample rate. Not unit-tested beyond the import guard; Task 10 runs it for real.
  - `analyze TRACK | --playlist NAME [--project P] [--root R] [--rekordbox D] [--repo DIR] [--force] [--keep-stems DIR] [--device cuda|cpu]`.
    - TRACK resolves through `Project.resolve`; `--playlist` reads the playlist from rekordbox and finds each track's SoundSwitch ref by the base name of the TrackMap path (compared like `find_audio`); a playlist track with no SoundSwitch ref or no script is reported and skipped.
    - Pool match: the pool entry with `same_track(ref.artist, ref.title, …)`; when several match, the one whose `norm(title) == norm(ref.title)`; still several or none → refuse (`add it to its pool first` / list them).
    - Map path `<repo>/lightshows/maps/<slug(pool "Artist — Title")>.yml`; kept when it exists and `not is_stale(...)` and no `--force`; else analysed and written.
    - Audio: `find_audio(root, ref.path)`, read with soundfile; sha256 of the file bytes, first 12 hex.

**Interfaces:**
- Produces in `set_timeline.py`:
  - `@dataclass Leg: name: str; map: dict; cues: dict[str, int]; tempo: tuple[float, float] | None` (played tempo at start and end; None = the map's first-anchor BPM).
  - `@dataclass Transition: out_name, in_name, g_bar: int, b_bar: int, offset_bars: int, overlap_bars: int, overlap_sections: list[tuple[str, int, int]], arrival_bar: int | None, peak_bar: int | None, clock_g_s: float, clock_arrival_s: float | None`.
  - `timeline(legs: list[Leg]) -> tuple[list[Transition], float, list[str]]`: transitions, the set's total seconds, warnings.
    - The outgoing leg's last bar = `bars` minus trailing `silences`. `offset_bars = b_bar - g_bar`. Overlap = last bar − g_bar + 1 (≥ 0). `overlap_sections`: the incoming map's sections clipped to `[b_bar, b_bar + overlap_bars - 1]`. Arrival: the first incoming drop with `bar >= last_out + offset_bars + 1`. Peak: the incoming drop with the largest `db` among those `< ` the incoming's own G bar (all drops for the last leg).
    - Set clock: leg 1 plays bars `1..G`, middle legs `B..G`, the last `B..last bar`, at the played tempo (linear ramp from start to end tempo over the leg's played bars); `clock_g_s` is the clock at the outgoing's G; `clock_arrival_s` at the arrival bar.
    - Warnings: missing B (not the first leg) or G (not the last) → that transition is skipped and named; a cue in `cues` whose `cue_text` differs from the map's `hot_cues` → `"<name>: hot cue G moved since the map (map 137.1, rekordbox 139.1); run cues"`; a cue not on a beat → named.
  - `block_tempos(block_text: str) -> list[tuple[str, str, tuple[float, float] | None]]`: `(artist, title, tempo)` per tracklist line; tempo from the field after the key: `122` → `(122, 122)`, `122-125` → `(122, 125)`; anything else → None.
  - `render_markdown(transitions, total_s, warnings) -> str` (one row per transition: `# | out G → in B | clock | overlap | in-sections | arrival | peak`) and `render_yaml(...) -> str`.
- Produces in `nextrack_map.py`: `timeline --playlist NAME [--block FILE] [--yaml]`; maps found by pool match like `analyze`; a track without a map is a warning and breaks the chain at that point.
