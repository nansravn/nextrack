# shows/ — the show language

A **show** is one night written as data: a palette, named looks, rules, and one cue list per
track, in set order. A compiler turns it into the per-track choreographies of
[`lightshows/tracks/`](../README.md#choreography-tracksartist-title-slugyml), the format that
`nextrack_lights.py` renders, compiles and applies. This file is the manual for the agents that
write shows. Everything the compiler needs is in YAML; logic lives in two Python registries,
[gestures](#gestures) (effects in time) and [rules](#show-rules) (budgets and bans).

```
anchors on the musical map  ->  cues  ->  looks / gestures  ->  sections  ->  lightshows/tracks/<slug>.yml
```

If you have just arrived, run `uv run scripts/nextrack_show.py vocab [<show-id>]`. It prints the
anchor grammar, each layer's words and mapping keys, every gesture and rule with its
parameters, and the show's palette and looks, always in step with the code.

## The loop

1. **Read the music.** `uv run scripts/nextrack_map.py show "<Artist — Title>"` gives the
   sections, the drops and the owner's hot cues. A track needs its
   [musical map](../README.md#musical-maps) (`lightshows/maps/<slug>.yml`) first; a map that
   fails its `musical-map` check counts as none, and the finding says
   `lightshows/maps/<slug>.yml is not a valid map: fix its musical-map finding`. `show`
   draws the sections as a strip of letters, one per bar; to write `<kind>.<i>` anchors, read
   the numbered list instead: `grep -E '^(bars|hot_cues|sections):' lightshows/maps/<slug>.yml`
   prints the bar count, the hot cues and the sections in order, and `break.3` is the third
   entry with `kind: break`.
2. **Edit the show:** `show.yml` (the night) or one track file (its cues).
3. **Build:** `uv run scripts/nextrack_show.py build <show-id>`. Findings come as
   `path:line: rule-id: message` and name the value and the fix.
4. **Read the night:** `uv run scripts/nextrack_show.py report <show-id>`: every section, what
   produced it, the music under it, the budget tally. Critique it as a whole.
5. **See a track:** `uv run scripts/nextrack_lights.py render "<Artist — Title>" --choreo lightshows/tracks/<slug>.yml -o <scratch>/sim.html`
   (needs the SoundSwitch project; the language does not).
6. Repeat from 2. **Never edit `lightshows/tracks/<slug>.yml` of a show**: it starts with the
   header `# Generated by scripts/nextrack_show.py build from ...` and the next build
   overwrites it. Writing into SoundSwitch (`apply`) stays the owner's call.

`check_repo.py` runs the same compile (`show-source`, `show-rules`, `show-compiled`), so a show
that is not built, or whose rules fail, never gets merged. `build` writes the files even when
only rules fail, so a draft can be rendered and critiqued; it then exits 1.

**Variants.** To try an alternative without touching the committed show, copy the folder
outside the repo, change it, and build with `--out`:

```bash
cp -r lightshows/shows/<show-id> <scratch>/variant
uv run scripts/nextrack_show.py build <scratch>/variant --out <scratch>/out
uv run scripts/nextrack_lights.py render "<Artist — Title>" --choreo <scratch>/out/<slug>.yml -o <scratch>/sim.html
```

`--out` writes the choreographies into that folder with no ownership check. A show folder
outside `lightshows/shows/` builds only with `--out`.

## The folder

```
lightshows/shows/<show-id>/
  show.yml                                   # the night
  <slug>.yml                                 # one cue list per track, named like its map
```

`<show-id>` is a kebab-case id, normally the stem of the light plan
(`lightshows/sets/<show-id>.md`). A track file is named `<slug>.yml`, where the slug is the stem
of the track's map (`lightshows/maps/<slug>.yml`), which is also the stem of the choreography
it generates. A wrong name is a finding that says the right one. The tracks of the show are
the tracks of the set (`set:` in `show.yml`: each block its program links, in order, and each
line of the block's `## Tracklist`). Every set track needs exactly one track file; a file for a
track that is not in the set is a finding; a track played twice in the set is a finding (a track
has one choreography). Order is never written in the show.

Names are kebab-case ids: lowercase letters and digits joined by single `-` (palette entries,
looks, cues, moments, shows). Prose (`story`, `intent`, `budget`) is pt-BR. Ids, keys and
values are English or pt-BR words as the owner's show uses them (`respiracao`, `breu`).

YAML gotchas: an unquoted `off`/`on` is read as a boolean. A layer written `off`/`on` is fine
(the compiler gives the words back), and booleans inside a layer mapping (`mirror: true`) stay
booleans. Write `1/4` without quotes (it is a string); quote anything starting with `#`, `&`
or `*` (`track: '&ME, Black Coffee — The Rapture Pt.III'`: unquoted, `&ME` is a YAML anchor
and the file does not parse). Inside single quotes an apostrophe is doubled (`'Can''t'`).

## `show.yml`

This example is the one the repo's tests compile (two tracks, a bridge and a handover):

```yaml
show_version: 1
set: sets/teste.md
story: 'Uma noite de teste: o azul abre, o vermelho fecha.'
palette:
  azul: '#0A2CFF'
  vermelho: '#FF0A2A'
  violeta: '#6A1CFF'
looks:
  respiracao:
    movers: {move: sweep, every: 2bar, positions: [Dance Floor Centre, Crossed Over], colour: azul, level: 0.7}
    matrix: {draw: rows-up, rate: 1bar, colour: azul, mirror: true}
    hue: {state: pulse, colour: vermelho}
  pulso:
    extends: respiracao
    movers: {move: blink, every: 1/4, colour: vermelho, positions: null, position: Crossed Over}
    matrix: {draw: centre-out, rate: 1/8, colour: vermelho}
  breu: {movers: off, matrix: off, hue: dark}
gesture_defaults:
  spiral:
    rates: [1/2, 1/4]
    colours: [azul, violeta]
    aims: [[Crossed Over, Up], Dance Floor Centre]
bridge:
  name: ponte
  intent: 'Ponte: a mesma luz da música anterior, até a chegada.'
handover:
  name: entrega
  intent: 'Entrega: do G até o fim, o look que a próxima copia.'
```

| key | |
|---|---|
| `show_version` | required: `1` |
| `set` | required: repo-relative path of the set (`sets/<set>.md`); the track order comes from it. An absolute path or one with a `..` part is a finding |
| `story` | required, pt-BR: the idea of the night |
| `palette` | required: name -> `#RRGGBB`. A `colour` in movers, matrix and hue may be a palette name |
| `plan` | optional: repo-relative path of the prose light plan (`lightshows/sets/<show-id>.md`), with the same check as `set` |
| `looks` | optional: name -> [look](#looks) |
| `gesture_defaults` | optional: gesture name -> parameters merged under every call of that gesture (the cue's `with` wins; `null` removes a default). Its problems land in `show.yml`: see [Gestures](#gestures) |
| `bridge` | optional: `{name, intent, bars?}`, `name` and `intent` required when `bridge` is present. Without it no bridges are made. `bars` (1-32) is the mix window: see [The handover and the bridge](#the-handover-and-the-bridge) |
| `handover` | optional: `{name, intent}`, both required when `handover` is present. The default `name`/`intent` of the handover sections of the track files; needed when a track's handover does not write its own |
| `rules` | optional: rule id -> parameters (or `true`). Chooses which [rules](#show-rules) run; none written, none run |
| `advice` | optional: rule id -> parameters, as in `rules` (a rule may be in both, with other parameters). Design goals: their findings (`show-advice`) are printed by `build` and `report`, and never fail `check_repo.py` or change an exit status |
| `identity` | optional: `{arc?, signatures?}`, what the night promises: see [identity](#identity) |

### identity

```yaml
identity:
  arc: single-peak                 # optional: single-peak | waves | slow-burn
  signatures:
    - name: azul-espaco
      intent: 'O azul é o espaço da noite: os feixes moram nele.'
      is: {movers.colour: [azul, violeta]}
      share: {min: 0.6}
    - name: coracao
      intent: 'O vermelho é o coração, no centro da sala.'
      is: {hue.colour: vermelho}
      share: {min: 0.5}
```

- `arc` is the shape of the night's energy: `single-peak`, `waves` or `slow-burn`.
- A signature is `{name, intent, is, share?}`. `name` is a kebab-case id (unique in the
  block) and `intent` is pt-BR prose.
- `is` maps dimensions to a value or a list of values (a list means any of them). The
  dimensions are `look`, `gesture`, `movers.move`, `movers.rate`, `movers.colour`, `aim`,
  `matrix.draw`, `matrix.rate`, `matrix.colour`, `hue.state` and `hue.colour`. A section carries
  the signature when every listed dimension matches. Colours are palette names, `look` takes
  looks of the show, `gesture` registered gestures, `aim` aim ids of `lightshows/room.yml`
  (a finding when there is no valid room), rates a rate word and `movers.move`, `matrix.draw`
  and `hue.state` the layer's words (`vocab` lists them).
- `share` is `{min?, max?}`, fractions of the night from 0 to 1 with `min <= max`.
- Every problem is a `show-source` finding at the signature's line, such as
  `identity.signatures[0].is: 'movers.color' is not a dimension`.
- The dimensions a signature declares are exempt from the dominance checks of the variety
  analyses: a conscious repetition is not monotony.

A compiled show also carries what the repo knows of the night: the played tempos of its tracks
(`check_repo.show_tempos`), the owner's energy labels (`check_repo.show_energies`: the `eN` of the
block's tracklist line, else the `energy` of the pool entry), the rig and the room, and the line
of each rule, advice and signature in `show.yml`.

## A track file

```yaml
track: Pedro Sampaio — Dançarina
story: 'Dançarina abre a noite: o azul respira, a espiral gira e a virada acende o vermelho.'
cues:
  - at: drop.1
    name: chegada
    role: arrival
    intent: 'A chegada: o azul respira.'
    look: respiracao
  - at: break.1
    name: espiral
    intent: 'Espiral: os lados revezam cada vez mais rápido.'
    gesture: spiral
    with: {bars: [2, 2]}
  - at: drop.2
    name: virada
    moment: virada
    accents: [white, strobe]
    intent: 'A virada: tudo em vermelho.'
    look:
      movers: {move: blink, every: 1/4, colour: vermelho, position: Crossed Over}
      matrix: {draw: solid, rate: 1/8, colour: vermelho}
      hue: {state: pulse, colour: vermelho}
handover:
  look: pulso
  moment: passagem
  accents: [white]
```

```yaml
track: Chiclete com Banana — Voa Voa (Ao Vivo)
story: Voa Voa recebe a ponte e fecha a noite com o rolo de estrobo.
budget: Um rolo de estrobo no último drop.
cues:
  - at: drop.1
    name: chegada
    role: arrival
    look: pulso
    with: {matrix: {draw: zigzag}}
  - at: break.1
    name: subida
    look: respiracao
    with:
      movers: {move: pingpong, every: 1/2, faster_from: 'drop.2 - 2', faster_every: 1/4, positions: null, position: Up, level: null}
  - at: drop.2
    name: final
    moment: final
    accents: [strobe-roll]
    look: pulso
```

Keys: `track`, `story` and `cues` (a list, possibly empty) are required; `budget` (pt-BR prose),
`handover` and `bridge` (only `false`: no bridge into this track, and no echo of it in the
track before) are optional.

**`track` is written exactly as the map's `track`** (`Artist — Title`, with the em dash). The
compiler finds the map by the same matcher the blocks use and says so when the text differs.

### Cues

A cue starts at an anchor and lasts until the next cue (a cue stack: no overlaps).

| key | value |
|---|---|
| `at` | required: an [anchor](#anchors), the cue's first bar |
| `until` | optional: an anchor, the first bar **after** the cue (exclusive); leaves a gap that stays on the autoscript |
| `name` | required: kebab-case; becomes the section name (a gesture derives its sections' names from it). May repeat in a track (`drop`, `corte`) |
| `intent` | optional pt-BR prose, copied to every section the cue makes (each step of a gesture) |
| `look` | a look name, or a mapping of layers. Exactly one of `look` and `gesture` |
| `gesture` | a [gesture](#gestures) name |
| `with` | optional. With `look`: layer overrides (see [Looks](#looks)). With `gesture`: its parameters |
| `role` | optional: `arrival`, the drop that shows the new track. Only the cue's first section carries it |
| `moment` | optional: a kebab-case moment name, as the light plan names its moments; the `budget` and `matrix-not-cloned` rules read it. Every section of the cue gets it |
| `accents` | optional list: `white` (one beat of the white strip on the cue's first beat), `strobe` (a strobe hit there), `strobe-roll` (a strobe roll over the cue's first section) |

Spans: a cue runs from `at` to the bar before the next cue's `at`, or to `until - 1` when it has
`until`. The last cue runs to the bar before the handover, or, with no handover, to the map's
last bar (the report lists each default end under "decided by the compiler"). `at` must
increase strictly. `until` must be after `at` and no later than the next start. Every cue
covers at least one bar. Accents go on the first section of the cue; an accent whose layer the
look already sets on that section is a finding (remove one of the two).

### The handover and the bridge

The **handover** is the look that plays from G to the end of a track and that the next track's
bridge copies. In the track file:

```yaml
handover:
  look: pulso              # a look name or a mapping of layers (required)
  with: {...}              # optional overrides
  at: G                    # optional anchor, default G
  until: end + 1           # optional anchor, default: after the map's last bar (with bridge.bars: at + bars)
  name: entrega            # optional, default: the show's handover.name
  intent: "..."            # optional, default: the show's handover.intent
  moment: passagem         # optional
  accents: [white]         # optional; accents stay on this track, the bridge ignores them
```

Unlike `show.yml`, where `name` and `intent` are both required, a track file's handover may omit
them and inherits the show's; with neither, it is a finding.

The **bridge** is made by the compiler, never written. When the show has `bridge`, the track is
not the first in the set, the track before it has a handover, the map has a hot cue `B`, and
the track file does not say `bridge: false`, the track opens with a section from `B` to the bar
before its first cue (or its handover, or the map's end), named and described by the show's
`bridge`, with exactly the layers of the previous handover (after merging and palette
resolution, without accents). The continuity of the night is that copy.

**`bridge.bars`** (optional, 1-32) is the length of the mix window, on both sides. The handover
runs by default from its start (`G`, or its `at`) for `bars` bars, not to the map's end, and an
explicit `until` past that is a finding at the handover. The bridge still runs from `B` to the
bar before the first cue, and a first cue (or handover) after `B + bars` is a finding there:
`the bridge ends at bar <B + bars - 1> (bridge.bars <n>); start a cue at or before bar <B + bars>`.
Without `bars`, nothing changes. The [`bridges`](#show-rules) rule measures the windows.

The **echo** is made by the compiler too, never written. With `bridge.bars` the handover can
end before its track does, while many mixes last longer than the window: the room hears both
tracks, and which script SoundSwitch plays then is still unknown (experiment
[P1](../../docs/soundswitch/experiments.md#playback-in-the-room-p)). So the compiler fills the
outgoing track's bars after its handover with the incoming track's light over the same
stretch of the mix, and the room sees one light whichever script plays. It exists when the
show has `bridge.bars`, the handover ends before the outgoing map's last bar (cut by the window
or by its own `until`), the next track opens with the bridge that copies that handover (so
`bridge: false` in the next track disables both), and both hot cues resolve (the outgoing
`G`, the incoming `B`).

- **What it copies.** The clock puts the incoming `B` on the outgoing `G`, so outgoing bar `k`
  is incoming bar `k - offset`, with `offset = G - B`. The outgoing bars from the one after the
  handover (`h_end + 1`) to the map's last copy the incoming compiled sections over
  `[h_end + 1 - offset, bars - offset]`, clipped to that stretch and shifted by `+offset`. The
  echo stops at the outgoing map's end or at the incoming track's last section, whichever
  comes first; a bar no incoming section holds there (a gap after an `until`) stays a gap: the
  autoscript.
- **What it leaves out.** It copies the states, not the events: the layers exactly, with
  `movers.faster_from` shifted by the offset (at least bar 1, which still means fast from the
  start), and without `white.accent`, `strobe.hit` and `strobe.roll`, raw or from `accents:`;
  a layer they leave empty is dropped, so it reads `auto`. An event belongs to the track that
  plays it. A copied `auto` stays `auto`.
- **Its sections** take the incoming sections' names and intents, and their record (see
  [Provenance and occurrences](#provenance-and-occurrences)).
- **The report** lists it under "decided by the compiler":
  `<outgoing title>: echo <a>-<b> copies <incoming title> <a - offset>-<b - offset>`. With the
  example show and `bars: 4`, Dançarina's handover is 25-28 and
  `Dançarina: echo 29-32 copies Voa Voa (Ao Vivo) 9-12` (G 25 - B 5 = 20).

If P1 shows that the switch follows the fader inside the window, the echo is harmless: the
outgoing script is just not seen.

Consequences, each a finding that says what to do:

- A track whose map has a `G` followed by a track that would take a bridge needs a handover.
- The next track needs a hot cue `B` (add it in rekordbox and run `nextrack_map.py cues`), or
  `bridge: false`.
- The next track's first cue (or handover) must start after `B`.
- A bar number in the outgoing track means nothing in the incoming one. A handover whose layers
  hold one (`movers.faster_from`, or a raw `white.accent`, `strobe.hit`, `strobe.roll`) is a
  finding **at the handover** when a bridge would copy it. Move the effect to a cue before the
  handover, or write `bridge: false` in the next track. (`accents:` are not copied, so they are
  fine.)

## Anchors

Time is anchored on the musical map; never count bars by hand.

```
anchor := term [ ("+" | "-") n ]
term   := n                  an absolute bar (from 1)
        | A … H              the bar of that hot cue in the map (`hot_cues`)
        | <kind>.<i>         the first bar of the i-th section of that kind (from 1)
        | <kind>.<i>.end     its last bar
        | end                the map's last bar
kind   := intro | groove | break | build | drop | outro
```

An anchor is a YAML integer (`16`) or a string (`drop.2 - 1`, `G`, `break.1.end + 1`; spaces
around the sign are optional). `drop.i` is the i-th section of kind `drop` (the same bar as
the i-th entry of the map's `drops`, whose `db` the report shows). A hot cue that is not on a
bar's first beat (`9.3`) cannot be an anchor. Every failure names what the map has, such as
`drop.4: the map has 2 drop sections (9, 21)` or `G: the map has no hot cue G (it has A, B)`.
A resolved bar must be inside `1 ... bars`, except for an `until`, which may also be
`bars + 1` (`end + 1`: the cue runs to the last bar). Note that `end` is the last bar itself, so
`until: end` leaves the last bar out.

`movers.faster_from` takes an anchor too. Every other bar in a layer (the raw `white.accent`,
`strobe.hit`, `strobe.roll`, written `"<bar>.<beat>"` or `[a, b]`) stays absolute, an escape
hatch; prefer `accents:`.

## Layers

A layer value is exactly the choreography vocabulary of
[lightshows/README.md](../README.md#layers): `movers`, `matrix`, `white`, `uv`, `strobe`, `hue`,
each `auto`, `off` or a mapping. `vocab` lists each layer's words and keys, the moves, draws,
hue states and rates. Three differences in a show:

- a `colour` (movers, matrix, hue) may be a palette name; `#RRGGBB` is still accepted;
- `faster_from` may be an anchor;
- a key set to `null` in a `with` override removes it (`with: {movers: {positions: null, position: Up}}`).

**Aim ids.** Where the movers take a SoundSwitch preset name (`position`, `positions`, a
gesture's `aims`, also from `gesture_defaults`), a kebab-case **aim id** of
[`lightshows/room.yml`](../README.md#the-room-roomyml) may stand instead: `position: cruzado`
compiles to `Crossed Over`. A `pending` aim (its preset is not in SoundSwitch yet) compiles to
the preset of the first `configured` aim along its `fallback` chain, and `report`
lists each such swap under "decided by the compiler". `vocab` lists every pending aim, the presets
the owner still has to create. An id that is not in the catalogue is a finding that names the
close ones (`positions 'cruzdo' is not an aim of lightshows/room.yml; did you mean 'cruzado'?`),
at the cue, or at `show.yml` when the aim came from `gesture_defaults`. An id with no valid
`room.yml` is a finding too. A preset name is kept as written: only kebab-case values are
read as aims.

A layer the look does not name stays `auto` (the autoscript). `haze` is not a layer: every
compile holds it. The compiler validates its output with the choreography's own checker; a
problem there (an unknown draw, a bad rate) is a `show-source` finding at the cue that produced
it, so you never need to read the generated file to find an error.

## Looks

A look is a mapping of layers with an optional `extends: <look>`. Merging is per layer. When
the base value and the override are both mappings their keys merge (the override wins, `null`
removes a key); otherwise the override replaces the base value, and `null` removes the layer.
A cue's `look: name` plus `with:` is the same merge applied on top. In the example, `pulso`
extends `respiracao`, replaces the movers' keys and the matrix draw, and keeps `hue` and
`matrix.mirror`. An unknown look (the message lists the defined ones and a close match), a
cycle of `extends` or a layer name outside the vocabulary is a finding. A look that is not used
anywhere is fine. Do not name a look like a gesture or an effect key (`spiral`, `strobe`...).

## Gestures

A gesture is a Python function in [`scripts/show_gestures.py`](../../scripts/show_gestures.py)
that fills the bars of one cue with sections. A cue invokes it with `gesture: <name>` and its
parameters in `with`; the show's `gesture_defaults` are merged underneath. The sections it
returns are named from the cue (`<cue name>-...`) and cover exactly the cue's span; bad
parameters are `show-source` findings at the cue, with the fix in the message.

A problem in `gesture_defaults` lands in `show.yml`, where the fix goes. A key the gesture does
not take is a finding there (with a close match), even for a gesture no cue calls. A bad value
that a cue takes from the defaults, because its own `with` does not set that parameter (a rate,
a palette name), is reported once at `show.yml`, ending `(from gesture_defaults.<gesture> in
show.yml)`, not in every track file that calls the gesture. A cue that sets the parameter
itself does not see the default's problem. A problem that depends on the cue (the bars do not
add up to its span) stays at the cue.

| gesture | parameters | what it does |
|---|---|---|
| `sequence` | `steps`: a list of `{bars, look, with?, name?}` | One section per step, consecutive; the bars add up to the cue's span. `look` is a look name or a mapping of layers, `with` is merged on top. A step's name defaults to `<cue name>-<i>` counted from 1. A step with `look: <name>` reports that look for the budget. The way to compose an effect in time from looks, with no new code |
| `spiral` | `bars`, `rates`, `colours`, `aims`: four lists of the same length, one entry per step | The v1 spiral, the relay that speeds up: the two sides take turns, faster step by step, centre dark. Per step: movers `pingpong` every `<rate>` in `<colour>` aimed at `<aim>`, matrix `columns` at `<rate>` with `pingpong`, hue `dark`. Rates are `1/16`, `1/8`, `1/4`, `1/2` or `<n>bar`. An aim is a preset name (`position`) or a list of them (`positions`). Bars add up to the span. Sections are named `<cue name>-<rate>` with the slash as a dash (`espiral-1-4`) |

A `sequence` cue, valid on the example above (a 4-bar span):

```yaml
- at: drop.2
  name: quebra
  gesture: sequence
  with:
    steps:
      - {bars: 2, look: respiracao}
      - {bars: 2, look: pulso, name: volta}
```

Adding a gesture is a code change with a test: see the checklist in
[CLAUDE.md](../../CLAUDE.md#change-checklists). Until then, compose with `sequence`.

## Show rules

A rule is a Python function in [`scripts/show_rules.py`](../../scripts/show_rules.py), chosen
and parameterised under `rules:` in `show.yml`. It reads the compiled show and returns
`show-rules` findings that point at the cue (or handover) to fix, in the file of the agent that
owns it. Bad parameters, or a rule id that is not registered, are `show-source` findings at
`rules:`. Rules run only when the show compiles.

```yaml
rules:
  budget:
    pulso: {max: 1}
    strobe: {max: 5, moments: [virada, final], from: "Pedro Sampaio — Dançarina"}
  total-dark: {only: [breu]}
  arrivals: {draw_differs: true}
  movers-aim: true
  matrix-not-cloned: {except_moments: [virada, final]}
  exclusive: {keys: [spiral, pulso], except_tracks: ["Pedro Sampaio — Dançarina"]}
```

| rule | parameters | finding when |
|---|---|---|

### Provenance and occurrences

The rules count **occurrences**, from the compiled sections, each with its provenance:

- `kind`: `cue`, `bridge`, `handover` or `echo`; `track`: the track whose choreography holds it;
- `look`: the name of the look that produced the section (the `look: <name>` of a cue or a
  handover, or the one a gesture step reports); empty for inline layers. `gesture`: for the
  sections a gesture made;
- `role` and `moment`: those of the cue, given to every section it produced (`role: arrival`
  marks only the first section);
- `path` and `line`: where a finding about this section points.

Provenance is per section, so a `sequence` step with `look: breu` counts as `breu`. A **bridge**
section takes the record of the handover it copies, in the outgoing track's file, so a finding
about a bridge lands in the file of the agent who owns the handover, which is where the fix
goes; a moment exception applies to the copy as it does to the original. An **echo** section
takes the record of the incoming cue (or bridge) it copies, with `kind: echo`, the outgoing
track as its `track` and no `role`, so a finding about it lands in the file that owns that
chapter. The rules that read sections (`total-dark`, `movers-aim`, `matrix-not-cloned`) skip
echoes: the original is checked where it is written.

| key | an occurrence is |
|---|---|
| a look name | a compiled section (not a bridge or an echo) whose look is that name: a cue or handover with `look: <name>`, or a gesture step that reports it (only the name used, not the looks it extends) |
| a gesture name | a cue that invokes it |
| `white-accent` | one beat of a `white.accent` list in a compiled section |
| `white-flash` | a compiled section with `white: {flash: ...}` |
| `strobe` | one beat of `strobe.hit`, or one `strobe.roll` |
| `uv` | a compiled section with `uv: on` or `movers.move: uv` |

Bridges and echoes never count: they copy a look already counted where it was written. An
`accents` entry produces a `white-accent` or `strobe` occurrence like the raw form does.

## The critic's views

`report` is the night read for a critic, and `zoom` is one moment under a magnifying glass.
Both are built from the compiled show and the musical maps (and `room.yml` to name aims). The
clock also reads the set's block tracklists for tempos and the owner's energy labels, the light
measures and the zoom read the rig, and the identity reads the set's `arc`; they read nothing
else. Every number below comes from a function in
[`scripts/show_views.py`](../../scripts/show_views.py),
[`scripts/show_energy.py`](../../scripts/show_energy.py),
[`scripts/show_analysis.py`](../../scripts/show_analysis.py) or
[`scripts/show_zoom.py`](../../scripts/show_zoom.py) whose docstring states its formula; the
report's text is [`scripts/show_report.py`](../../scripts/show_report.py)'s.

### Clock

The set clock is `set_timeline`'s model. Each track plays bars: the first from bar 1, a middle
track `[B, G)`, the last up to its last non-silent bar. The tempo is the block tracklist's range,
ramped linearly over the played bars; without one, the map's `bpm`. A bar past `G` of the
outgoing track runs at its end tempo, and the next track starts at the previous one's `G`.

### Two windows per track

- The **leg** of a track is `[B, G)`: from its hot cue `B` to the bar before `G` (the first
  track plays from bar 1, the last to its last non-silent bar). It is the track's share of
  the night's time.
- The **sounding window** runs from the leg's first bar to the track's last compiled bar, so
  it includes the handover that still sounds after `G`.
- **States** (looks, colours, aims, zones lit, dark) are **summed over legs**: during a mix
  the time belongs to the incoming track, whose bridge copies the outgoing handover, so no
  moment is counted twice. An echo lies past its track's `G`, outside its leg: it adds no
  state.
- **Events** (accents, strobe, UV, moments, map drops) are listed **over sounding windows**,
  at their own clock. An echo makes none (its events stay with the incoming track), but it
  extends the outgoing sounding window to its last bar, so a map drop under it is a peak.

### Levels

Every bar of a track's sounding window gets digits 0-9: the music's energy, the light's
energy and the light's two parts. They are measurements with stated formulas, normalised to
the track or the night, never lux or decibels.

**Normalisation.** A feature `x` is read as `x^ = clip01((x - p5) / (p95 - p5))`, the 5th and
95th percentiles taken over a **scope**: the track's leg bars (the *track scope*) or every
track's leg bars (the *night scope*). When `p95 - p5` is below `1e-9` every `x^` is 0.5. A digit
is `round(9 x ...)`, halves rounded up.

**Music energy** `E_music(b) = round(9 x (0.4 L^ + 0.2 C^ + 0.2 D^ + 0.2 V^))`, from four
features of bar `b`:

| feature | read from |
|---|---|
| `L` loudness | the map's `mix.loudness` digit ([the mix block](../README.md#musical-maps)) |
| `C` brightness | the map's `mix.brightness` digit (the share of power above 4 kHz) |
| `D` onset density | the bar's 1/16 steps with a `kick` or `perc` onset of strength 3 or more, over 16 |
| `V` texture | the voices (vocals, kick, perc, bass, other) whose bar digit is 6 or more, 0-5 |

The strips, the peaks and `follows` use the track scope; the label check (`arc`) the night
scope. A map without `mix` (version 1) uses the **interim** formula
`round(9 x (0.5 D^ + 0.5 V^))`, and every view that uses it names the track `<title> (interim)`.
The section lines keep the voices (`k9 b7 v0 p8 o7`) apart.

**The light** is sampled the way `zoom` samples it (`show_zoom.sample_light`): the compiler's
own generators, one sample per 1/16 step, 2 ms after the step's start, for each fixture group of
the rig. A step no section holds reads unknown everywhere (the autoscript plays); a strobe that
is `auto` is unknown, one that is `off` or not lit at that instant is off; a Vorlane's coverage
(the lit share of its colour cells) is unknown when any colour cell is `auto`. A bar is
**unknown** (`~`) when any of its 16 samples has an unknown mover, Vorlane or lustre. Otherwise
each group has a level 0-1 at every step (an unknown white, strobe or coverage counts 0):

| group | level at a step | weight |
|---|---|---|
| movers | the mean of the movers' levels | 0.35 |
| Vorlanes | the mean over the Vorlanes of level x coverage | 0.35 |
| lustre | the hue's level | 0.15 |
| white | the white strip's level | 0.10 |
| strobe | 1 when a strobe window is lit, else 0 | 0.05 |

- **Brightness** `B` is the weighted sum of each group's mean level over the bar's 16 steps.
- **Activity** `A` is the weighted sum of each group's rises, over 16. A rise is a step whose
  level is 0.05 or more after a step below it (the first step compares with the bar before's
  last sample, or at a leg's first bar with the previous track's last leg sample; an unknown
  sample, as the autoscript's, counts no rise), so a strobe pulse is a rise. For the Vorlanes a step counts the share of their
  colour cells newly lit there (a column of eight lighting up is 1/8), averaged over the
  Vorlanes: the highest cell would hide a sweep of single columns.
- **`E_light(b) = round(9 x (0.5 B^ + 0.5 A^))`**, with `B` and `A` normalised over the night's
  known leg bars. The strips also print `bright` (`round(9 x B^)`) and `activity`
  (`round(9 x A^)`) apart: a drop that is dimmer but much faster is a legitimate design, and the
  critic must see it. The weights are a design call, stated here.
- **Change events** `X(b)`: how many of nine dimensions change value at bar `b` against bar
  `b - 1` of the same track (0 at the window's first bar): `movers.move`, `movers.rate`,
  `movers.colour`, `aim`, `matrix.draw`, `matrix.rate`, `matrix.colour`, `hue.state` and
  `hue.colour`. With `look` and `gesture` in front, the eleven values are the section's
  **signature**: two sections with the same signature look the same to the critic.

An unknown bar is left out of every statistic and counted in the summary's `light unknown`
share. `~` has the same meaning in the strips, the peaks, the hit checks and the zoom lanes.

### What `report` prints, in order

Real excerpts of `report hi-ibiza-pulso`, cut to width. Its sections, in this order, are
`summary`, `tracks`, `peaks`, `hits`, `follows`, `drops`, `builds`, `variety`, `arc`, `identity`,
`budget`, `arrivals`, `advice`, `decided` and `findings`. Each starts with a header line (`peaks`,
`follows`, ...), most with a line naming their columns, then one line per item.

**The night summary** (`summary`, `night 44:09`): the time per look, the time per colour of each
zone (movers, matrix, hue), the aims, how much of the night each zone is lit, the centre dark,
the total dark, the events (`white-accent 5 (0:02)`: count and time) and the time whose light
is unknown. States (looks, colours, aims, zones, dark) are summed over legs; events are counted
over sounding windows.

```

  looks: inline 29:02, respiracao-azul 7:42, pulso-vermelho 2:20, contraluz 1:44, ...
  aims: centro-da-pista 19:40, cruzado 15:09, coluna 4:59, lado-leste 1:26, lado-oeste 1:26, poca 0:23, cabine 0:18

  light unknown: 0:00 (0%), the autoscript decides
```

**The tracks** (`tracks`): the legend, which names the measures and points here, then per track
a **header** (bars, `B`, `G`, when it enters, when its arrival lands, `(interim)` for a map
without `mix`) and the four **strips**: one digit per bar, 64 bars to a row, `music` (E_music),
`light` (E_light), `bright` and `activity`, each row labelled with its first bar:

```
1. &ME, Black Coffee — The Rapture Pt.III · 209 bars · G 169 · enters 0:00 · arrival 145 at 4:48
  music       1 |5556665566656555666665566666666666666666666566646676676776767767|
  light       1 |0000000021111111322222222222222244444444444444445555555555555555|
  bright      1 |0000000022222222555555555555555588888888888888888888888888888888|
  activity    1 |0000000020000000100000000000000000000000000000001111111111111111|
```

Then the section lines, each with its **clock** (`0:16`, the set time of its first bar) and,
at the end, the music under it with the **voices** (`k9 b7 v0 p8 o7`: the highest level of
kick, bass, vocals, perc and other over the section's bars):

```
  0:16 9-16 primeiro-feixe | look (inline) | movers pingpong every=8bar position=centro-da-pista ... | music: groove 9-16, k9 b7 v0 p8 o7
```

**The peaks** (`peaks`): one row per map drop inside a sounding window, by clock: the drop
against the two bars before it (`+22.0 dB`; a drop after silence reads huge), E_music at the drop
(track scope), E_light of the bar before and of the drop (`0>8`), the accents there and the
moment. On a track's `B` the bar before is the previous track's last leg bar. A bridge's or an
echo's copied moment is never shown as the moment of its drop.

```
  32:18 · Too Cool To Be Careless 49 · +22.0 dB · music 7 · light 0>8 · accents white,strobe · moment virada
```

**The hit checks** (`hits`): one row per arrival and per moment (the first section of a cue or
handover with a `moment`; never a bridge or an echo): the strength of the kick onset on the first
1/16 step (`kick 9`; `.` none), E_light before and at the hit, the accents on its first beat,
and, when the section before is total dark, the voices over those dark bars:

```
  32:18 · Too Cool To Be Careless 49 · moment virada · kick 9 · light 0>8 · accents white,strobe · dark before: 48-48 k0 b0 v9 p1 o0
```

**follows**, one line per track, over the leg's bars with a known light:

- `rho`: the Spearman correlation (of average ranks; `-` below 3 bars or for a constant side) of
  E_music (track scope) and E_light.
- `agree`: the map's section starts `s` with `leg first + 4 <= s <= leg last - 3` are the
  boundaries; at each, `dm` is the mean E_music over `s..s+3` minus over `s-4..s-1`, and `dl` the
  same for E_light. Among the boundaries where the music moves (`|dm| >= 2`), the share where the
  light moves the same way by 1 or more.
- `lag`: the shift in -8..8 bars that best correlates the music with the light shifted (Pearson;
  a tie goes to the smaller shift; `-` below 16 known bars); `+` means the light is late, and a
  lag beyond 1 is flagged.
- `missed`: the boundaries where the music moves and the light moves less than 1, with `dm` and
  `dl`. `unmotivated`: where the light moves 3 or more and the music less than 1 (for
  information). `unknown`: the share of the leg whose light is unknown.

```
  The Akan · rho 0.50 · agree 50% · lag 0 · missed 105 (music +4.5, light +0.8) · unmotivated - · unknown 0%
```

**drops**, every sounding map drop `d` in rank order of its **salience**
`S = 0.4 L^ + 0.3 bass + 0.2 D^ + 0.1 main`:

- `loud`: the mean `mix.loudness` over `d..d+3` minus over `d-8..d-1` (a version 1 map: E_music);
- `bass`: the bass's return, `max(0, bass digit at d - lowest bass digit over d-8..d-1) / 9`;
- `density`: the same rise as `loud` on the onset density;
- `main`: the track's drop with the largest loudness rise, or its last drop;
- `L^` and `D^` divide by the night's largest rise (0 when none rises).

Its light **response** is `0.5 clip01(contrast / 4) + 0.25 changes / 9 + 0.25 fresh`:

- `contrast`: the mean E_light over `d..d+3` minus over the 2 bars before (the previous track's
  at a leg's first bar);
- `changes`: `X(d)`;
- `fresh`: the share of the drop section's nine dimension values that no section sounding in
  the 10 minutes before has.

`agreement` is the Spearman of salience and response over the drops above the median salience.

```
  rank 1 · 39:30 · PICK UP THE PHONE (feat. Nate Dogg) (Extended) 137 · salience 0.90 (loud +5.0, bass 1.00, density +0.70, main) · response 0.64 (contrast +5.5, changes 5, fresh 0.00)
  rank 2 · 7:12 · The Akan 105 · salience 0.84 (loud +6.0, bass 1.00, density +0.18, main) · response 0.22 (contrast +0.0, changes 7, fresh 0.11)
  agreement: rho -0.05 of salience and response over the drops above the median salience
```

**builds**, each map `build` of 4 bars or more and the last 4-16 bars of a `break` that a `drop`
follows: the slope per bar (least squares) of the music's tension (the mean of the loudness,
brightness and onset density normalised over the leg; a version 1 map: the density alone), the
slopes of the light's activity and brightness digits, and how the light goes **into** the drop
`d`. It is `dip` when E_light at `d - 1` is at least 1 under its mean over `d-9..d-2`; else `ramp`
when the build's last 4 E_light never fall and end above its first; else `flat`. It is `unknown`
when the autoscript plays a bar the test needs.

```
  6:56 · The Akan 97-104 · music +0.075 · activity +0.11 · brightness +1.36 · into ramp
```

**variety**, over the legs' time:

- **static runs**: the five longest stretches of one signature, across a leg boundary too (then
  both tracks are named: `Dançarina 21 – Voa Voa 8`), with the map sections under them.
- **per minute**: one digit per minute `m` of the night, the entropy of the signatures' time
  shares over `[60 m - 120 s, 60 m + 120 s)`, `-sum(p log2 p) / log2(k)` for `k` signatures
  (0 for one), as `round(9 x H)`.
- **dominant**: per dimension, the value (not `auto`) with the largest share (a value of several
  words, such as a section's aims, shares its time among them), `(declared)` when a signature
  of the identity names it.
- **similarity**: the cosine of two neighbouring tracks' shares of every dimension value; the bars
  of a bridge section (the copy of a handover) are left out of both vectors.
- **drop templates**: the distinct pairs (signature before the drop, signature at it) against
  the number of drops.
- **phrase lines**: the share of the bars with a change event that start a map section or fall
  on a 4-bar line from one.
- **uses**: per track, the looks, colours per zone, aims and gestures its legs use, and its
  number of distinct drop templates: the record the designers read.

```
  5:36 · The Akan 57-96 · 1:20 · groove
  per minute, 0-9, the entropy of the signatures over 4 minutes: |988887877878878888877888888887788877787888888|
  dominant movers.colour: azul-gelo 86%
  similarity The Akan / What To Do (&ME Remix) 0.97
  drop templates: 32 distinct of 35 drops
  phrase lines: 78% of the light's changes start a map section or fall on a 4-bar line from one
```

**arc**, the night against the owner's energy (each track's `eN` from its block line, else the
pool's): per track the mean and the 90th percentile of E_light over its leg, the mean activity
digit, the share of its leg with a warm colour (movers or lustre within 30 degrees of red) and
its rare resources (strobe, white, UV and total-dark counts, gesture calls). Then the checks,
each `-` when nothing is listed:

- `rho`: the Spearman of the owner's energy and the light mean, and of the energy and the p90.
- `headroom`: the highest p90 before the first track at the night's top energy, over the
  night's highest p90.
- `staircase`: a track whose p90 beats every earlier p90 while its energy is below an earlier
  one.
- `step`: neighbours whose light mean jumps by 2 or more at the same energy (`jump`), or moves
  less than 1 while the energy rises (`flat`).
- `no breather`: a drop of the top quarter by salience with no bar at or below the night's median
  E_light within 3:00 after it.
- `label`: a track whose rank by owner energy and by measured E_music (night scope) differ by
  three or more: a question for the owner, never a fix.

```
  5:36 · The Akan · e6 · light 3.8, p90 4.0 · activity 0.7 · warm 90% · rare -
  rho 0.00 (mean) and 0.13 (p90): the owner's energy against the light per track
  headroom 0.89: the highest p90 before the first track at the night's top energy, over the night's highest
  step jump: Say What -> Baianá (Pablo Fierro Edit): energy e7 -> e7, light mean 2.9 -> 5.2
  label: The Akan: owner energy e6 ranks 13.5, measured music ranks 1: check the label
```

**identity**: the arc (the identity's `arc`, else the set's front-matter `arc`, else `none`),
then each declared [signature](#identity): the share of the night its sections hold against its
`share` bounds (`in range`, `below min` or `above max`) with its intent, and one line per
occurrence (its clock, bars and length). Then, per dimension, the most present value no
signature declares.

```
  arc: single-peak (the set's)
  signatures: none declared
  undeclared movers.colour: azul-gelo 86%
```

Then the budget tally, the arrivals, the **advice** (`show-advice` lines), "decided by the
compiler" (bridges, default ends, aim fallbacks, a handover cut by `bridge.bars`, echoes) and
the findings. `report` exits 1 when it printed a finding; advice never does.

**Filters.** `--section a,b` prints only those sections, in the order above; an unknown name is a
usage error that lists them. `--track "<Artist — Title>"` (the track as its file names, as
`zoom` takes it; an unknown one is a usage error that lists the tracks) prints a slice for one
designer:

- the legend, then the previous track's handover (and echo) lines under `N. <track> · handover`;
- the track's header, strips and section lines;
- the next track's bridge lines under `N. <track> · bridge`;
- in every other section, the lines that name the track: its peaks and hit rows, its follows
  and builds lines, its drops, the variety and arc lines that name it, the identity occurrences
  in it, the budget lines that count it, its arrival, the advice and findings of its file and
  the compiler's decisions about it.

A section with no such line is left out, and so is the summary. A slice of Hï Ibiza is 5 000 to
10 000 characters. The two combine: `--track X --section follows,drops`. The exit status
follows what is printed: 1 only when a finding is among the printed lines.

### `zoom`

```bash
uv run scripts/nextrack_show.py zoom <show> <moment>                          # the first cue or handover with that moment
uv run scripts/nextrack_show.py zoom <show> "<Artist — Title>" <anchor>       # a bar of a track, by anchor
uv run scripts/nextrack_show.py zoom <show> virada --before 3 --after 2       # bars around it (default 3 and 1)
uv run scripts/nextrack_show.py zoom <show> virada --frames 48.4,49.1         # also the Vorlanes' 8x7 cells at those beats
```

It prints one column per 1/16 step, a `|` at each bar line, the music from the map and the
light **as `compile` would write it** (it samples the compiler's own generators). It needs no
SoundSwitch project. An unknown moment is a usage error that lists the moments. From

- A mover, a Vorlane unit or the lustre gets one glyph per step: the colour's legend letter,
  upper case at or above half level and lower case below it, `.` when dark; `~` is the
  autoscript. The legend printed under the table names each letter.
- The **uv lane shows intent only**: UV is not compiled yet (X11), so it is a manual cue.

  lists them.

### Reading the report as a critic

What is **fact**: the clock and durations, what each layer does in each section, the energy
digits (measured with the formulas in [Levels](#levels)), the voices and drops in the maps,
which hits land on a kick, the analyses' numbers, the budget counts, the advice that does not
hold. What is **left to judgment**: whether a light of 3 under a drop of 9 is the right
restraint, whether a dark bar before a drop is tension or a hole, whether a low `rho` is a
missed cue or a counterpoint, whether two arrivals look alike, whether an aim fits the figure
the music draws. The digits are relative (to the track or the night), never lux or decibels; a
`~` is a gap in what the tool can know, not a defect. Read the strips for the shape of the
night, `follows` and `arc` for how the light tracks the music and the plan, the peaks, the hit
checks and `drops` for the moments that must land, `variety` for repetition, the `zoom` for the
1/16 steps of one moment, and `render` for what the room sees. A number that looks wrong is a
question about the formula, which is in this section, before it is a question about the show.

## `brief`

`uv run scripts/nextrack_show.py brief <set>` (a path, or the stem of `sets/<stem>.md`) prints
the music of a set before any show exists, for the person who designs it. The text is generated
from the set, its blocks, the pool and the maps; the same inputs give the same bytes. Headers,
in order:

- `night`: the length (the set clock's total), the set's `arc`, the blocks with their
  `function` and `energy`, the tempo ramp (first start to last end, and the extremes).
- `tracks`: per track, `enters` (the start of its leg on the set clock), the leg's minutes and
  bars, `B`, `G`, the mix window (bars from `G` to the map's last bar), the played tempo, the
  owner's energy (`eN` of the tracklist line, else the pool's `energy`), the night-normalised
  `E_music` mean and 90th percentile over the leg's bars (see [Levels](#levels); `(interim)`
  for a map without `mix`), the vocal presence (the share of leg bars whose vocals digit is 6
  or more), and a strip of one letter per leg bar, the letters of `nextrack_map.py show`
  (`i` intro, `g` groove, `b` break, `u` build, `d` drop, `o` outro).
- `drops`: every drop in a sounding window, ranked by the salience of `drops` in the report
  (`S = 0.4 L^ + 0.3 bass_return + 0.2 D^ + 0.1 main`, from the maps alone; a tie goes to the
  earlier on the clock), with its clock, bar and `main` mark.
- `target`: the owner's energy per minute, one character each (1-9, `X` is 10): the tracks'
  energies at their legs' starts joined by straight lines, flat at the ends, read at the middle
  of each minute and rounded half up.
- `labels`: the label check's questions, as in `arc`: owner energy rank against measured
  `E_music` rank, three places or more apart. Questions for the owner, never a fix.
- `missing`: a track with no map or an invalid one (the clock leaves it out), a map without
  `mix`, a track with no hot cue `B` (not the first) or `G` (not the last).

## UV (designed, not compiled)

UV makes people and the room glow (white clothes, UV-reactive decorations); it barely shows in
haze, so it is not a beam effect. Until [X11](../../docs/soundswitch/experiments.md) finds where
SoundSwitch stores a mover's UV, `uv: on` and `move: uv` stay manual cues and the `uv` budget
key counts them. The design, to implement after X11: dark first (Vorlanes off or deep blue,
lustre `dark`, white strip off), UV moments of at least 4-8 bars, pure UV on the movers aimed at
the floor and the people (`centro-da-pista`, `rasante`, a sweep between `lado-oeste` and
`lado-leste`), a `uv` layer with `{pulse: steady | beat | offbeat | perc, level}`, a gesture
`uv-glow`, and the rules `uv-needs-dark` and `uv-min-bars`. It is UV-A only, and a beam never
rests at eye height. The full design is in
[the critic's spec, section 9](../../docs/superpowers/specs/2026-11-06-show-critic-design.md#9-uv-designed-implemented-after-x11).

## Who owns a choreography

`build` writes `lightshows/tracks/<slug>.yml` with a two-line header naming the show. The rules
of ownership:

- `build` overwrites a choreography that has the header of this show.
- A hand-written file (no header) is refused: `refused <path>: not generated by a show; use --adopt to take it over`.
  `--adopt` takes over only hand-written files (the first build of a ported set).
- A file owned by another show is always refused. The conflict is resolved in the shows, not
  by a flag; the validator also reports a track owned by two shows.
- With any refusal, nothing is written.
- `build --check` writes nothing and prints `would change <path>` per file that differs; exit
  1 if any does.
- `build` and `build --check` print `stale <path>: owned by this show, which no longer compiles
  it; delete it` for a file with this show's header whose track the show no longer compiles.
  Neither deletes it; both exit 1 until it is gone.
- `build --out DIR` writes elsewhere with no ownership check (variants, above).

The emitted text is deterministic (layers in a fixed order and key order, flow style), so the
same show gives the same bytes. `show-compiled` fails when a committed choreography is missing
or differs from what its show compiles to; the message says to run `build <id>`, or, for a
hand-written file, `build <id> --adopt` to take it over.

**Porting hand-written choreographies.** Copy the stories, budgets and intents verbatim, build
with `--out <scratch>/out` first and compare each generated file with today's one, parsed
(`yaml.safe_load`; the emitted file quotes `"off"`, so read a top-level `False` as `off`): the
header and the formatting change, the data must not. Only then run `build <id> --adopt`, once.

## Writing a show, start to finish

1. Pick the set (`sets/<set>.md`) and make sure every track has a map. `nextrack_map.py show`
   each track; note its drops, breaks, and hot cues `B` and `G` (the numbered sections: see
   [the loop](#the-loop), step 1).
2. Write `show.yml`: `story`, `palette`, a few `looks`, `bridge` and `handover` (if the night
   flows through bridges), and `rules` last.
3. Write one track file per track, named `<map slug>.yml`, `track` copied from the map. Start
   with the arrival (`role: arrival`) and the handover; add cues with anchors where the music
   names the bar (a section start, a hot cue, `drop.2 - 1` for the bar before a drop). A bar
   number is for a cue the light places inside a section.
4. `build`. Fix findings from the top. Then `report`, and critique the whole night: budgets,
   arrivals, what repeats.
5. `render` the tracks that matter; iterate.
6. `uv run scripts/check_repo.py` and `uv run pytest` before calling it done.
